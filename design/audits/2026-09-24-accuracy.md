# Audit 1 — Accuracy

24 September 2026. Does every quiz item claim only what its source says?

Re-run it any time:

```
node pipeline/audits/accuracy.js          # the table below
node pipeline/audits/accuracy.js --all    # with the soft notes
node pipeline/audits/accuracy.js --json   # machine readable
```

It takes under a second and exits 1 while any hard failure stands.

## The five hard failures

### 1. The fingerprint card states a rank it has not tested

**202 claims in 149 of the 191 fingerprint items.** `app/js/quiz-bank.js:332`.

The card says, for example: *"That is Alfred and Plantagenet. Its jobs are led
by health & social (18%) and public administration (16%)."* That sentence makes
two comparisons. It puts health & social ahead of public administration, and it
makes public administration the second sector rather than the third. Neither is
gated.

In 88 items the first pair is not separated at the app's own three-standard-
deviation gate; in 114 items the second pair is not. Two examples, re-derived
straight from `app/data/work_csd.json`:

- `B1:3544018` — retail 1,230 against health & social 1,225. A gap of 5 where
  the gate needs 286. Both print as 17%, so the card names an order between two
  figures it prints as identical.
- `B1:3523043` — health & social 520 and agriculture & resources 520. Exactly
  tied, and the card names one of them second.

This is the defect QUIZ-DESIGN §2 principle 2 was written about: "v1 separated
the answer from the runner-up, then stated an unseparated rank on the card". It
came back in a different sentence. 26 of the 202 are within a fifth of the
threshold; the rest are not close.

**Current (`quiz-bank.js:327-335`):**

```js
  function topWords(v) {
    var t = total(v);
    var r = v.map(function (x, i) { return { i: i, x: x || 0 }; })
      .sort(function (a, b) { return b.x - a.x; }).slice(0, 2);
    return 'led by ' + D.naics[r[0].i].short.toLowerCase() + ' (' +
      pct(r[0].x / t) + ') and ' + D.naics[r[1].i].short.toLowerCase() +
      ' (' + pct(r[1].x / t) + ')';
  }
```

**Replacement:**

```js
  /* G1 applies to everything the screen states, not only the answer
     (QUIZ-DESIGN principle 2). So a second sector is named only where the
     second clearly beats the THIRD - otherwise it is not the second - and the
     two are put in order only where the first clearly beats the second.
     Where either test fails, the card names the largest group and stops. That
     is still a true sentence, and it is shorter to read. */
  function topWords(v) {
    var t = total(v);
    var r = v.map(function (x, i) { return { i: i, x: x || 0 }; })
      .sort(function (a, b) { return b.x - a.x; });
    var one = D.naics[r[0].i].short.toLowerCase() + ' (' + pct(r[0].x / t) + ')';
    if (!clear(r[0].x, r[1].x) || !clear(r[1].x, r[2].x)) return 'led by ' + one;
    return 'led by ' + one + ' and ' + D.naics[r[1].i].short.toLowerCase() +
      ' (' + pct(r[1].x / t) + ')';
  }
```

The question itself is untouched: the fingerprint asks which place a profile
belongs to, and that answer is separated. Only the card sentence changes.

### 2. The twin card claims a size restriction the search does not apply

**4 items.** `app/js/quiz-bank.js:522`.

The card says *"of any place its size in Ontario"*. The candidate pool is every
census subdivision with 2,000 jobs or more — not a size band. So the search
compares a 67,000-job city with a 16,500-job one and calls them the same size.

- `C3:3553005` and `C3:3556027` — 67,115 jobs against 16,565. A factor of 4.1.
- `C3:3537013` — 7,350 against 2,845. A factor of 2.6.
- `C3:3516010` — 20,115 against 7,975. A factor of 2.5.

**Current (`quiz-bank.js:521-523`):**

```js
          sentence: names[0] + ' has the most similar mix of jobs to ' +
            optName(p) + ' of any place its size in Ontario.',
```

**Replacement — say what was actually searched:**

```js
          sentence: names[0] + ' has the most similar mix of jobs to ' +
            optName(p) + ' of any place in Ontario with 2,000 jobs.',
```

That is 18 words, inside the card limit. The alternative is to make the claim
true instead of the sentence: add `Math.max(ta,tb)/Math.min(ta,tb) <= 2` to the
pool filter. That keeps the nicer wording and costs about four items.

### 3. "People travel in to work" where more workers leave than arrive

**2 items.** `app/js/quiz-ideas.js:722`.

The size question that survived the v3 cut is *"X has more people. Which has
more jobs?"*, and its card explains the surprise with *"People travel in to
work."* In two items the winning place has clearly fewer jobs than working
residents, so the net flow runs the other way.

- `A1:3507004-3507040` — 2,420 jobs, 2,915 working residents (ratio 0.83).
- `A1:3534005-3534042` — 1,580 jobs, 1,980 working residents (ratio 0.80).

Four more sit inside sampling error and are soft notes, not failures.

**Current (`quiz-ideas.js:720-722`):**

```js
        it.card.sentence = H.optName(hi) + ': ' + H.about(H.total(H.vec(hi.code, 'total'))) +
          ' jobs, against ' + H.about(H.total(H.vec(lo.code, 'total'))) +
```

**Replacement — the explanation only where the inflow is real:**

```js

        it.card.sentence = H.optName(hi) + ': ' + H.about(H.total(H.vec(hi.code, 'total'))) +
```

## How the checker keeps quiet

Every rule has a stated tolerance, and the tolerance is built from two things
only.

**1. What was printed.** The app prints counts at two significant figures
behind "about", percentages whole (or to one decimal below 10%), location
quotients to one decimal, and rates as "N in 10". Whatever the format, a
printed number may sit up to half of its last printed digit from the true one.
The checker reads that half-step off the printed string, so no format needs its
own rule: `about 4,200` gives 50, `9.3%` gives 0.05, `37` gives 0.5.

**2. Census rounding.** Every published cell is randomly rounded to a multiple
of 5. METHODS §7.1 derives a standard deviation of 2.0 per cell and 2√m for a
sum of m cells. The checker allows two of those, 4√m. It only bites on small
counts.

```
tolerance  =  half the last printed digit  +  4 × √(cells behind the figure)
```

**Sampling error is deliberately not added.** Both sides of a numeric check are
the same published estimate read twice, so sampling error is common to both and
cancels. Adding it would gut the check — a 1.92√n band on a 10,000-job cell is
190 jobs, which would let a generator be wrong by 190 and pass. Sampling error
belongs where the app puts it: in the separation gate for comparisons, not in
the recomputation of a printed figure.

**Comparisons are tested with the app's own gate**, `M.clearlyLarger` at z = 3
on `M.countSd`, and with `sdCI` on the published intervals where the payload
carries them. The audit does not invent a second standard.

**It does not rebuild what `validate.py` already checks.** Section 10 of
`pipeline/validate.py`, through `pipeline/quiz_selftest.js`, already covers one
correct option, duplicate option labels, the universe chip (G4), the date chip
(G5), confusable names (G9), stem and card word length, id collisions, bank
size and idea coverage. Those are structural. This audit is about truth.

## Tuning, and the false-positive rate

The first draft raised **234 flags** (219 hard, 15 soft). I went through them
and found **6 that were the checker's fault, not the app's — 2.6%**. Each was
established the same way: recompute the figure from the raw JSON in
`app/data/` with a separate Python script that does not use the app's loader at
all, then read the generator line that wrote the sentence.

1. **2 flags — a parser fault.** `about()` drops the word "about" below 100, so
   "Pickle Lake: about 320 jobs, against 95." did not match a regex that
   required "against about". Fixed by making the word optional.
2. **3 flags — a rule that was too broad.** The METHODS.md rule demanded that
   every number in a glossary term appear in the section it cites, and flagged
   the numeral 1 in "Above 1 is an employment centre that draws people in".
   That is where a ratio is neutral, which is arithmetic, not a claim about a
   method. Now 0, 1 and 100 are exempt, with the reason in a comment.
3. **1 flag — a name collision.** A new check resolved an option label back to
   a place by name, and "Hamilton" matched Hamilton Township in Northumberland
   rather than the City of Hamilton, so `B4:3550:71` looked wrong. Option
   labels are now resolved inside the item's own economic region, and the
   concentration check rebuilds its candidate set from the region rather than
   from labels.

I also **moved 4 flags from hard to soft** rather than deleting them: the
"People travel in to work" items whose jobs ratio sits just under 1, inside
sampling error. Calling those wrong would be crying wolf; dropping them
silently would hide a sentence that is not earning its keep.

**After tuning: 229 flags, 0 measured false positives.** All 27 flags outside
the fingerprint class were checked one at a time. For the fingerprint class I
took a seeded random sample of 15 of the 202 and re-derived each pair of counts
from `work_csd.json` in Python, with the standard deviation worked out by hand
from `1.92√n` — all 15 were correct.

The residual risk is the other direction: a claim form nobody wrote a rule for
would pass in silence. The script guards against that. Any item whose form or
id matches no rule raises a soft note saying so, and none do today. Add a
question form and the audit will ask for a rule.
