# Audit 5 — Design and UX on a phone, measured in numbers

**Module:** the Learn tab and the quiz (question and learning module)
**Screen:** 375 × 812 CSS px, both light and dark
**Date:** 2026-09-24
**Probe:** `pipeline/audits/ux_probe.js` (re-runnable; the header says which screens to open, in what order)
**Nothing under `app/` was changed.** Every fix below is a proposed patch, not an applied one.

## 6. The largest text setting — the headline finding

The comparison app had one part of the quiz ignoring the reader's text size. **Hinterland has none that obey it.**

**Measured:** root font-size moved 16 → 20 → 24 px. **0 of 15** measured quiz elements changed size. Page height stayed at **1,095 px** at all three settings (answer screen), **425 px** (question), **756 px** (Learn landing).

**Why:** `app/css/app.css` declares `font-size` **202 times, every one in px**, starting with `body { font-size: 15px }` (line 198) and `@media (max-width: 720px) { body { font-size: 17px } }` (line 1457). There is not one `rem`, `em` or `%` font size in the file.

Every quiz class the brief asked about is px-fixed:

| Selector | Line | Size | Scales? |
|---|---|---|---|
| `.qstem` | 1085 | 20px | ✖ |
| `.qopt` | 1103 | 17px | ✖ |
| `.qlabel` | 1111 | inherits 17px from `.qopt` | ✖ |
| `.qkey` | 1109 | 14px | ✖ |
| `.qsentence` | 1127 | 17px | ✖ |
| `.qtag` | 1117 | 14px | ✖ |
| `.qchip` | 1082 | 14px | ✖ |
| `.qverdict` | 1121 | 19px | ✖ |
| `.qlesson-pts li` | 1294 | 17px | ✖ |
| `.qlesson-t` | 1291 | 26px | ✖ |
| `.qlesson-ask` | 1292 | 17px | ✖ |
| `.qprog-t` | 1346 | 15px | ✖ |
| `.qmore > summary` | 1130 | 15.5px | ✖ |
| `.qmore-p` | 1131 | 16px | ✖ |
| `.qsource` | 1128 | 14px (15px on phones) | ✖ |
| `.qconf-b` / `.qconf-l` | 1093 / 1089 | 15px / 14px | ✖ |
| `.qnext` | 1150 | 17px | ✖ |
| `.term-chip` | 995 | 14.5px (15px on phones) | ✖ |
| `body` | 198 / 1457 | 15px / 17px | ✖ |

**What this means in practice:** page **zoom** still works (px scales with zoom), but the reader's *font size* setting does not — that setting only moves text sized in rem / em / % / keywords. On iOS this means Dynamic Type is ignored outright; on desktop the browser's "Font size" preference is ignored; on Android the platform text-scaling setting is unreliable against px.

**Fix (F1, the single most valuable change in this audit):** keep the design exactly as it is and change only the unit. `html { font-size: 100% }`, then divide every quiz `font-size` by 16 and write it in `rem`. At the default setting the rendering is pixel-identical; at 125% and 150% the whole quiz grows together.

**Secondary finding — the app's own reading floor is not met.** The stylesheet's comment at line 1447 says "body 17px, secondary 15px, nothing below 13px (chart labels only)". These quiz classes sit at 14 px on a phone: `.qchip`, `.qtag`, `.qkey`, `.qconf-l`, `.qidea-s`, `.qpic-note` — and `.qmisread` at 14.5 px. **Fix (F26):** raise them to 15 px (0.9375rem).

**Reflow:** at 320 px wide there is **no horizontal scrolling** (scrollWidth = clientWidth = 320) — WCAG 1.4.10 passes. Horizontal scrolling starts below about **234 px** of effective width, i.e. above roughly 150% page zoom on a 375 px phone. The widest unbreakable block is `.qchip` at 222 px. **Fix (F27, minor):** allow the chip to wrap — `.qchip { display: block; width: fit-content; max-width: 100% }`.

## 7. Back behaviour — this part is right

Every back affordance was exercised. **Back never dropped the reader to the top of a screen and never left the app unexpectedly.**

| From | Affordance | What happened | Scroll on return |
|---|---|---|---|
| Learn tile (Words, scrolled to 1,500) | back chevron `.tb-back` | Learn landing | **restored to 26** (where it was) ✔ |
| Learn tile (Words, scrolled to 1,500) | phone back (`history.back()`) | Learn landing | **restored to 26** ✔ |
| Learn landing | phone back | previous screen in history (Practise) | 0 (a different screen) ✔ |
| Learn landing, **fresh tab, first screen** | phone back | stayed on Learn; history state `base`; app not closed | unchanged ✔ |
| Words (scrolled 1,500) → Home → phone back | phone back | Words | **restored to 1,500** ✔ |
| Lesson | quiz chevron `.qback` | Paused ("Everything you have answered is saved") | n/a ✔ |
| Lesson | phone back | Paused | n/a ✔ |
| Question | quiz chevron | Paused | n/a ✔ |
| Question | phone back | Paused | n/a ✔ |
| Answer | phone back | Paused; **the answer was kept** (resume returned to the marked card) | ✔ |
| Paused | "Carry on" | back to the exact phase (lesson / question / answer) | **top of screen, not where you were** ⚠ |
| Paused | phone back | "Session finished — you answered 0 questions" | ⚠ |
| End of session | phone back | leaves the quiz to Practise | 0 ✔ |

**Fix (F28, comfort):** pause → "Carry on" returns to the top. On a 1,095 px picture answer that loses up to 283 px of position. Store `main.scrollTop` in `run` when `QU.pause()` fires and restore it with the existing `A.jump()` after the re-render.

**Fix (F29, comfort):** phone back from **Paused** ends the session and shows a summary reading "You answered 0 questions", which is a dead end that looks like a loss. Make back from Paused return to Practise instead (`QU.leave()` rather than `QU.stop()` when `run.asked === 0`).
